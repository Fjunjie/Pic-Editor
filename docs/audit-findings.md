# M1 审计意见对比与处置

审计范围：PR #1（`main...M1`）。本表记录 CodeHawk 与 ZCode 的交集、差异及本次修复决定。

| 问题 | CodeHawk | ZCode | 结论与本次处置 |
| --- | --- | --- | --- |
| 大图预览宽高比变形 | 未发现 | P1 | **成立，P1。** JS 设置等比内联尺寸后，CSS 的独立 `max-width` / `max-height` 会再次钳制单边。本次移除画布的 CSS 尺寸上限，让 `fitCanvas` 成为唯一的尺寸决策方。 |
| 导出分辨率低于源图、界面仍显示源尺寸 | 未发现 | P2 | **成立，P2。** 预览有 2400px 最长边上限，原实现会导出预览画布。本次导出时用原图重新渲染，并在完成状态中显示导出尺寸。 |
| JPEG 一律导出 PNG | 未发现 | P2（附带观察） | **不作为缺陷修复。** M1 的按钮和范围明确为 PNG；JPEG/WebP 格式与质量控制留给后续导出设置。 |
| `originalImage` 未使用 | 未发现 | P2（附带观察） | **已随全分辨率导出消除。** 原图对象现在用于构建原始分辨率的导出画布。 |
| 画布区外文件拖放会导航离页 | 未发现 | P2 | **成立，P2。** 本次在 `window` 级拦截文件拖放，避免浏览器打开文件导致未导出的编辑丢失；在非画布区域落下时给出反馈。 |
| “正在渲染”反馈不可见 | 未发现 | P3 | **成立，P3。** 原实现会在同一绘制周期显示并隐藏。本次使用双 `requestAnimationFrame`，确保重渲染前至少有一帧能呈现反馈。 |
| 偏好 JSON 恢复无容错 | P3 / LOW | P3 | **成立，P3。** 本次捕获解析错误，并只接受非数组对象与字符串字段。 |
| 键盘查看原图可能卡住 | 未发现 | P3 | **成立，P3。** 本次在窗口级监听释放按键，并在窗口失焦或页面隐藏时复位预览；导出也独立于当前“查看原图”状态。 |
| 不能重新选择同一文件 | P2 / MEDIUM | P3 | **成立。** 本次在读取 `File` 后立即清空 file input，以确保每次选择都触发 `change`。严重度定为 P2（体验缺陷、无数据损坏）。 |

## 验证重点

1. 2400px 以上图片的预览尺寸仅由 `fitCanvas` 控制，显示宽高比与源图一致。
2. 4000 × 3000 源图的 PNG 导出仍为 4000 × 3000；预览可以是 2400 × 1800。
3. 键盘或窗口失焦后，原图对比状态不会残留；导出始终应用当前调整。
4. 非法 `luma-api-preferences`、重复选择同一文件、以及画布外拖放均不会中断编辑器。
