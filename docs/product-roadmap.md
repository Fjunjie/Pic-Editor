# 智能图片编辑器：产品与交付设计

## 1. 产品目标

构建一个浏览器端图片编辑器：用户可以先通过直观的滑杆完成基础调色和美颜，再用画笔/套索圈定区域，通过自然语言让 AI 精确修改该区域。用户自带或自选的模型 API 配置保存在浏览器本地，避免将密钥写入前端代码或仓库。

### 核心体验

1. **快速调色**：上传图片后，色温、色彩（自然饱和度）、饱和度、对比度等调节即时反映在画布上。
2. **自然美颜**：用低破坏性的强度控制提供瘦脸、美白、磨皮，并支持前后对比和一键还原。
3. **局部 AI 编辑**：用户圈定区域、输入自然语言意图（如“把天空变成日落”），预览生成结果后再应用。
4. **可控连接**：在设置中配置兼容 OpenAI 的图片编辑接口、模型名和 API Key；密钥仅留在本地存储，生产环境由服务端代理请求。

## 2. 信息架构与主要界面

```
顶部栏：品牌 | 打开图片 | 撤销/重做 | 导出
左侧工具栏：调整 | 美颜 | 局部 AI | 历史
中央画布：原图/编辑预览、缩放、适配、局部蒙版叠层
右侧面板：当前工具的参数、预设、应用/重置操作
设置弹窗：接口地址、模型、API Key、连接测试、隐私说明
```

桌面端以双栏画布工作区为主，小屏幕将工具面板收纳为底部抽屉。每一项可编辑操作是一个非破坏性 `EditOperation`；渲染器按操作列表从原图生成预览，以支持撤销、重做和导出。

## 3. 技术方案

| 层级 | 方案 | 说明 |
| --- | --- | --- |
| 前端 | Vite + 原生 ES Modules（M1） | 轻量、零框架锁定；在复杂状态增长时可平滑迁移到 React。 |
| 画布渲染 | HTML Canvas 2D + `ImageData` | M1 的调色在浏览器实时完成，图片不上传。 |
| 状态模型 | `EditorState` + 操作栈 | 原图不可变；调节值、蒙版、AI 结果均为可撤销操作。 |
| 美颜能力 | 浏览器端人脸关键点/分割（后续） | M2 采用 MediaPipe 或等价 WASM 模型，默认本地推理。 |
| AI 编辑 | 后端 `/api/image-edits` 代理 | 服务端读取用户密钥/凭据引用、校验请求、转发至兼容图片编辑 API。 |
| 配置与安全 | `localStorage`（M1 原型）→ 加密凭据库（生产） | M1 仅演示配置字段；不会提交或自动发送 API Key。 |

### 数据模型（目标态）

```ts
type EditOperation =
  | { kind: 'adjust'; values: AdjustmentValues }
  | { kind: 'beauty'; faceId?: string; values: BeautyValues }
  | { kind: 'ai'; prompt: string; mask: BlobRef; result: BlobRef };

type ApiProfile = {
  baseUrl: string;
  model: string;
  apiKeyRef: string; // 指向受保护存储，不在操作记录或日志中出现
};
```

## 4. 里程碑

### M1 — 本地调色工作区（本次开发）

**目标**：交付可运行、无服务端依赖的基础编辑器原型。

- 图片拖放/文件选择、画布预览与空状态。
- 色温、色彩（自然饱和度）、饱和度、对比度四项滑杆；实时预览、重置、前后对比、导出 PNG。
- 工具栏、参数面板、响应式布局和键盘可访问性。
- 设置弹窗：接口地址、模型、API Key 输入与本地保存提示；不调用真实 API。
- 建立 `EditorState`、Canvas 渲染边界和未来工具入口。

**验收标准**：在 Chrome/Edge 打开后可载入 JPEG/PNG，以四项滑杆预览变更，按住“查看原图”可比对，并可导出当前画面；刷新后 API 非敏感配置可恢复。

### M2 — 自然美颜与编辑历史（已实现）

**目标**：增加本地优先的肖像处理与完整撤销体验。

- 使用浏览器本地 `FaceDetector`（可用时）检测人脸，并提供画布手动框选作为兼容回退，支持脸部选择。
- 瘦脸、美白、磨皮强度调节；未检测到人脸时给出明确引导。
- 基于操作栈的撤销/重做、编辑历史、调色与美颜参数预设。
- 大图缩放、按行分块渲染和预览耗时提示。

**验收标准**：单张人像可使用三项美颜并撤销/重做，非人像不崩溃；1080p 预览在常见桌面设备上保持可交互。

### M3 — 局部选择与 AI 编辑闭环

**目标**：使用户可以对任意选区用自然语言编辑。

- 笔刷、橡皮、套索/矩形选区，羽化与蒙版可视化。
- 对话式提示词、建议提示词、生成中状态和结果对比。
- `/api/image-edits` 代理与兼容 API 适配器；仅向用户配置的端点发送原图、蒙版和提示词。
- 失败重试、取消生成、生成历史和结果应用。

**验收标准**：可圈选局部并完成一次支持的图像编辑请求；结果仅影响选区，可放弃或应用，网络与供应商错误均可理解地呈现。

### M4 — 安全、项目与导出质量

**目标**：把原型提升为可日常使用的产品。

- 服务端会话与受保护密钥存储、CORS/速率限制、审计脱敏。
- 多图片项目、自动保存、版本快照、跨设备恢复。
- JPEG/WebP/PNG 导出、尺寸/质量设置、元数据与透明背景控制。
- 可访问性、国际化、隐私中心与端到端测试。

**验收标准**：凭据不出现在浏览器日志、导出符合选项、关键编辑流程具备自动化测试与可访问性基线。

### M5 — 模型生态与协作（可选）

**目标**：支持多个模型供应商与团队工作流。

- 多配置档、能力探测、模型/成本提示。
- 共享项目、评论、审批、批量处理和团队角色。
- 用量统计、配额与企业级部署选项。

## 5. 风险与边界

- **不要把 API Key 作为前端请求头直接用于生产**：M1 的表单只用于演示配置；M3 起必须经后端代理或安全密钥服务。
- **美颜偏见与过度处理**：默认强度温和，所有效果可撤销，并给用户明确的“原图”比较方式。
- **AI 结果不可预测**：局部蒙版、预览确认和操作历史是必要的产品护栏。
- **大图性能**：M1 先限制预览画布最大边长，M2 通过离屏画布/分块渲染优化。

## 6. 本次交付范围

本次实现至 M2。本地调色、美颜、脸部选择和编辑历史均在浏览器处理像素；局部选区绘制、对话生成以及真实 API 调用将在 M3 接入。设置界面保留字段和隐私说明，但不会储存 API Key。
